# 查證 .adb：用 MCP API，而不是翻原始碼、也不是掃位元組

## 三條鐵律（每條都對應一次真實失敗）

1. **不要對 `.adb` 做位元組 grep。** 正文的標籤以 **id 編碼**，`grep '<聯 i="' x.adb` 一定得 0 筆。
   把 0 筆當成「資料不存在」的證據是錯誤結論的最常見來源。要查內容一律走解碼路。
2. **不要為了查內容而抽全文。** 用 `info`／`search`（必要時 `variants` 做異體字搜尋）定位，
   需要才 `read` 一小段；回報時**只記行號、頁欄與計數**。把整本經文倒出來既慢又容易造成
   不應外流的原文副本。
3. **行號是行表，不是文字裡的 `\n`。** 把 source 區塊串接後 `split('\n')` 會得到「1 行」這種答案。
   行級內容要用 `lineText(i)`／`read` 的行級介面取；跨區塊邊界的行在拼接時**不可插入分隔字元**
   （插入會截斷跨界座標字串，造成假的 FAIL）。

## 標準流程

1. `adb_list` — 確認要查的庫在不在、路徑對不對。
2. `adb_info` — 讀檔頭：庫名、行數、區塊數、大小。先知道規模再決定怎麼抽樣。
3. `adb_tags` — 列出標籤種類與計數。要判斷「這份有沒有某一層結構」看這裡，不看正文。
4. `adb_toc` — 取目錄樹與節點的行號／VA 範圍。要驗「樹形是否真的巢狀」時，
   **必須用消費端實際那條建樹路**（介面用的那支），命令列 `toc` 走的是另一條，兩者結果可能不同。
5. `adb_search` — 定位。注意漢字判定要用 `\p{Script=Han}`（帶 `u` flag），
   不要用 `[一-鿿]`：後者漏掉擴充區的字，會造出假的「找不到」與錯位窗。
6. `adb_read` — 只取需要的行／段落；用它確認窗的首尾文字，而不是自己重組。

## 座標系要注意的事

有兩套座標系在流水線裡同時存在，混用必錯位：

- **VA／字元偏移**：搜尋引擎回傳的位置，**含標點**。
- **漢字偏移**（`j="起-迄"`）：頁內只留漢字後的索引。

兩者每頁可差一二成。把 VA 偏移直接拿去漢字串 `indexOf` 會永遠找不到——
那看起來像「這句話不在這頁」，其實是沒換算。跨頁／跨欄同理：句子起點在欄尾時，
要按既有慣例**鉗到頁尾發半句並記錄**，而不是改指別欄或放棄。

## 地址與鍵的規則

- 跨庫地址若含頁碼，而頁碼在**多冊重複**（實測大正有超過八成組合跨冊重複），
  鍵一定要帶冊號；少帶就會靜默查到別冊。
- id 常帶零填充（`02p108a` vs `2p108a`）；比對前一律**先解析再轉數字**，不要做字串相等比較。

## 查證指令碼的寫法紀律

- **同一個判定只允許一份實作**：需要重新數別指令碼已數過的東西時，優先呼叫它或共用它的提取規則。
  兩份實作遲早漂移（真發生過：兩支指令碼對同一記錄判定不同）。
- 探針的結論要附「怎麼量的」（來源、口徑、樣本還是全掃）。凡「全庫規則」的斷言**必須全掃**，
  抽樣只能給趨勢。
- 探針本身也要被驗：至少對一個已知存在、一個已知不存在的例子跑過（正控＋負控），
  否則你無法區分「資料沒有」與「尺壞了」。

## 交付時怎麼回報

- 附**可重現的坐標**：庫名、行號、頁欄、條目 id，以及使用的指令。
- 沒實據的一律寫「未驗證」；不要為了讓結論好看而圓話。
- 若需要閱讀器配合才能修，附上檔名＋行號＋重現資料＋「修好之後可以對的數字」，
  讓維護者不需重新調查就能動手。
